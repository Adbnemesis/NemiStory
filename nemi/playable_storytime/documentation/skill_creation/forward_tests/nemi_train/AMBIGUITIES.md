# Skill ambiguities and decisions encountered

1. **Fixed runtime versus measure-then-choose duration.** The brief fixes exactly 3:00. The skill's step 3 says measure dialogue, then choose/lock duration. I treated the user's explicit 180s as fixed, proposed the exact native map, and deferred internal timing lock until final measured audio; restructure/rewrite inside 180s rather than padding. A useful clarification would explicitly separate a user-fixed clock from a freely chosen clock.
2. **Phone support is conditional.** YouTube documents app 360 playback and manual chapter requirements, but this channel's eligibility and current app chapter/360 combination were not inspected. Phone chapters and description-time recovery are proposed routes requiring an exact-upload real-phone test; there is no universal custom tapping behavior. The skill appropriately warns against overclaiming, but cannot itself satisfy 'easy on phone' without access.
3. **Canonical production folder versus isolated helper root.** New episodes belong in `nemi/episodes/epNN_*`, while the actual playable helpers constrain their root to `nemi/playable_storytime`. The pipeline reference identifies a scoped adapter or validated canonical integration, but does not provide one ready route for a fresh production. Implementation has a real integration decision; I did not invent a working helper command outside its root.
4. **New premise requires actual renderer work.** The supported object/event lists have school/drawing assets, not globe/train/points/brake. The skill supports extending schema/profile/example/tests but does not specify generic imported environment art. I planned an explicit maintained station extension rather than silently treating new kind names, a generic bridge or a label as station support. This is a production prerequisite, not a blocker to this plan.
5. **Review dimensions wording.** 'Complete1920×1080 directed and spherical reviews' in the QA prose can imply a 16:9 spherical review. The repository architecture/schema distinguish 1920×1080 directed and 2160×1080 (2:1) spherical review, with 3840×1920 native spherical 4K. I used those explicit dimensions.
6. **Planning versus canonical preflight boundary.** The skill requires preflight before scripting/animation and the canonical route gates the actual direction brief. This evaluation explicitly prohibits actual episode/source authoring or persistent project mutations. I read the routing/reference material, saved only a hypothetical plan in /private/tmp, and left full episode-specific reading/acknowledgment pending production. No prepared/validated receipt is represented by this plan.
7. **Platform facts versus observed behavior.** Primary YouTube docs confirm digit percentage seeks, player focus/K, 360 playback and chapter requirements. They do not establish that this proposed file preserves orientation/pause in each current app or that actual chapter choices render. Those remain explicit future tests. I omitted WASD from the instruction example despite official support because the exact-file test has not happened.

No skill/global/episode files were changed. The complete skill and its three primary linked references were read. A large first batched read was truncated, so missing storytime/game-direction text was read separately; no preflight reading receipt was generated from any truncated output.
